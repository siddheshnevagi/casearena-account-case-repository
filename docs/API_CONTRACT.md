# API Contract — Module 2 (Account Management & Case Repository)

This is the integration contract for **Team 1 (AI Trainer)** and **Team 3
(Multiplayer Group Preparation)**. It documents what this module exposes so
the other two modules can build against it without reading the
implementation. If you change a response shape or a route here, update this
file in the same commit — it is the thing other teams are told to read
(PRD §9: "the auth interface is a Week 2 handover").

Base URL (local dev): `http://localhost:8000`
Interactive OpenAPI docs (auto-generated by FastAPI, always in sync with the
real code): `http://localhost:8000/docs`

## Authentication

All endpoints except `POST /auth/signup`, `POST /auth/login`,
`POST /auth/refresh` and `POST /auth/verify` require an `Authorization:
Bearer <access_token>` header.

Tokens are JWTs signed with `HS256` using `JWT_SECRET_KEY` (see
`backend/.env.example`). Payload shape:

```json
{
  "sub": "<user_id>",
  "email": "user@example.com",
  "is_admin": false,
  "exp": 1234567890,
  "type": "access"
}
```

**For Team 3**: to validate a token in your own service without calling back
into this module, decode it with the same `JWT_SECRET_KEY` /
`JWT_ALGORITHM` (shared via whatever secret-sharing your deployment uses —
Secret Manager in production, a shared `.env` in local dev) and check
`exp` and `type == "access"`. Do not accept `type == "refresh"` tokens for
API calls — refresh tokens are only valid at `POST /auth/refresh`.

Access tokens expire after `ACCESS_TOKEN_EXPIRE_MINUTES` (default 30 —
this is the "session timeout" in PRD FR-02). Refresh tokens expire after
`REFRESH_TOKEN_EXPIRE_DAYS` (default 7).

### `POST /auth/signup`
```json
// request
{ "email": "student@iiml.ac.in", "password": "at-least-8-chars" }
// response 201
{ "id": 1, "email": "student@iiml.ac.in", "is_verified": false,
  "verification_token": "…", "verification_token_note": "dev_only: emailed in production, see ADR-04" }
```
Fails `400` if the email is already registered, `422` if the password is
under 8 characters.

### `POST /auth/verify`
```json
// request
{ "token": "…" }
// response 200
{ "message": "account verified" }
```

### `POST /auth/login`
```json
// request
{ "email": "student@iiml.ac.in", "password": "…" }
// response 200
{ "access_token": "…", "refresh_token": "…", "token_type": "bearer", "expires_in": 1800 }
```
Fails `423 Locked` if the account has 5+ consecutive failed attempts (see
`locked_until` on the user) — response includes `retry_after_seconds`.
Fails `401` on a wrong password (and increments the failure counter).

### `POST /auth/refresh`
```json
// request
{ "refresh_token": "…" }
// response 200
{ "access_token": "…", "token_type": "bearer", "expires_in": 1800 }
```

### `GET /auth/me`
Returns the authenticated user's `id`, `email`, `is_admin`, `is_verified`.

## Profile & onboarding

### `POST /profile/onboarding`
Completes onboarding. Idempotent — calling again updates the profile rather
than erroring (used by "edit profile after onboarding", FR-05).
```json
// request
{ "target_firm_type": "CONSULTING", "case_preferences": ["M&A", "Pricing"] }
// response 200
{ "user_id": 1, "target_firm_type": "CONSULTING",
  "case_preferences": ["M&A", "Pricing"], "onboarding_completed": true }
```
`target_firm_type` must be `"CONSULTING"` or `"PRODUCT_MANAGEMENT"` —
mandatory per FR-03. `case_preferences` is optional, any subset of the case
taxonomy (see below).

### `GET /profile/me` / `PATCH /profile/me`
Same shape as above; `PATCH` accepts partial updates.

### `GET /dashboard`
```json
{
  "profile": { "target_firm_type": "CONSULTING", "case_preferences": ["M&A"] },
  "recommended_cases": [ /* Case objects, matching firm type ordered first — FR-04 */ ]
}
```

### `DELETE /account/me`
Deletes the account. Shared cases are retained per **ADR-03**: the response
confirms how many cases were anonymized vs. hard-deleted.

## Case repository

**Case taxonomy** (frozen per PRD §9 — this is the schema Team 1 depends
on; do not change without updating this document and notifying Team 1):

- `case_type`: `PROFITABILITY | MARKET_ENTRY | MERGERS_ACQUISITIONS | PRICING | OPERATIONS | OTHER`
- `difficulty`: `EASY | MEDIUM | HARD`
- `industry`: free text, optional

### `GET /cases`
Query params: `case_type`, `difficulty`, `industry`, `q` (keyword, matches
title + tags, minimum 3 characters per FR/AC), `sort`
(`newest` default | `most_practiced`), `scope` (`community` default |
`mine`), `page`, `page_size` (default 20, max 100).

```json
{
  "items": [
    { "id": 1, "title": "…", "case_type": "MERGERS_ACQUISITIONS",
      "difficulty": "HARD", "industry": "Retail", "tags": ["M&A", "retail"],
      "contributor": "Jane D.", "is_shared": true, "practice_count": 4,
      "created_at": "2026-07-01T12:00:00Z" }
  ],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "is_empty": true
}
```
`is_empty: true` is a convenience flag for the empty-state UI required by
US-04's acceptance criteria ("clear empty state … option to reset
filters") — the frontend does not need to compute it from `total`.

### `GET /cases/{id}`
Full case detail. `404` if it doesn't exist, is unshared and you're not the
owner/admin, or has been admin-removed.

### `GET /cases/{id}/file`
Streams the underlying PDF. Same visibility rule as above.

### `POST /cases` (multipart/form-data)
Fields: `file` (PDF, ≤10 MB — FR-09), `title`, `case_type`, `difficulty`,
`industry` (optional), `tags` (optional, comma-separated). Created private
(`is_shared: false`) in the caller's personal repository. `413` if the file
exceeds 10 MB, `415` if it isn't a PDF — both with a specific error message
per the AC in US-04B.

### `PATCH /cases/{id}` / `DELETE /cases/{id}`
Owner only (FR-11). `403` otherwise.

### `POST /cases/{id}/share` / `POST /cases/{id}/withdraw`
Owner only. Share makes the case visible under `scope=community`; withdraw
removes it from that view while keeping it in the owner's personal
repository (US-04B AC).

### `POST /cases/{id}/practice`
Increments `practice_count`. **This is the integration point for Team 1**:
when a user completes a case in the AI Trainer, call this endpoint so
"sort by most practised" (FR-08, Should-have) reflects real usage. No
request body; returns the updated case.

### `PATCH /cases/{id}/moderate` (admin only)
```json
// request
{ "removal_reason": "copyrighted casebook material" }
```
Soft-deletes the case (`is_removed: true`) per FR-11 and PRD §11 risk
mitigation. `403` for non-admin callers.

## Error shape

All error responses use FastAPI's default `{ "detail": "…" }`, or
`{ "detail": [...] }` for `422` validation errors. No custom envelope —
keep it standard so both frontend and other teams' clients can rely on
FastAPI's generated OpenAPI schema without a bespoke parser.
